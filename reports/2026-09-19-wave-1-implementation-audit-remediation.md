# Wave 1 implementation and 0.74.1 audit remediation

Date: 2026-09-19
Branch: `feat/wave-1-implementation`
Source design: `reports/2026-09-19-wave-0-wave-1-design.md`
Source audit: `reports/2026-09-19-harness-audit.md`

## Outcome

The lazy-harness portion of ADR-059 through ADR-062 is implemented. The 0.74.1
audit's repository changes are also implemented: completed queue tasks have a
seven-day retention policy, `reports/**` is in the documentation short-path
allowlist, and the two vulnerable dependencies are updated.

The implementation required two corrections to the proposed designs:

- ADR-060 no longer accepts a root-only Claude Code guarantee. Installed-binary
  evidence showed that a parent `CLAUDE.md` does not expand imports in nested
  sessions, while direct `AGENTS.md` discovery does. The repository now has one
  canonical `AGENTS.md`, conditional runtime sections inside it, no
  `CLAUDE.md`, and a static gate that rejects shadowing files at root, nested
  and hidden in-project paths.
- ADR-062 requires a unique `generated by lazy-harness` marker outside Markdown
  fences. A human-authored heading with the same title is never an opt-in.

## Implemented

### ADR-059 — portable skills

- Adapters declare their measured native skill root.
- Deploy plans all selected profiles before writing, rejects global name
  collisions and owns individual projections through a ledger.
- Cleanup removes only links still pointing into managed profile sources.
- Existing Claude profiles with an owned whole-directory `skills` symlink are
  migrated to per-skill links. An identical unrecorded symlink remains
  user-owned and causes a collision instead of being adopted.

The installed Codex discovery behaviour was already measured in both
directions. Repeating that probe against a skill projected by the released
harness remains binary-first rollout work after merge and release.

### ADR-060 — portable repository instructions

- `AGENTS.md` is the only repository instruction surface.
- `lh repo instructions [path]` fails when root `AGENTS.md` is absent or any
  in-scope `CLAUDE.md` shadows it.
- The repository gates itself through `tests/docs/test_repo_instructions_gate.py`.
- Governance, contributor docs, ADR index, backlog and roadmap describe the
  measured single-file contract consistently.

The `CLAUDE.md` deletion is intentional. It is a governance change, not an
edit event; the final diff and this report explicitly record it.

### ADR-061 — billed and API-equivalent cost

- MetricEvent v4 and SQLite store billed and API-equivalent measures
  independently, with source/status/basis metadata.
- Pricing happens per response using the response timestamp, not the session
  filename date, with an explicit session-date fallback for readers lacking a
  timestamp.
- Sol uses its documented 2026-09-19 through 2026-11-21 promotional window;
  Astra is priced only on its observed 2026-09-19 date.
- Response prices retain sub-micro precision until presentation.
- Once any response is unpriced, a later priced response cannot leave the
  aggregate with `status=priced` and `cost=null`.
- SQLite records the highest received event schema version so a late v3 replay
  cannot erase v4 enrichment, while v3 then v4 still enriches one logical row.

Receiver deployment, transcript backfill, outbox drain and Grafana changes are
separate rollout steps and remain explicit roadmap items.

### ADR-062 — bounded project state

- Compound-loop recognises real Claude Code and Codex transcript message
  shapes for interactivity, user-character weighting and prompt extraction.
- Project matching derives the canonical checkout from
  `git rev-parse --path-format=absolute --git-common-dir`, so main checkouts,
  worktrees and nested directories resolve to the same PRJ.
- The publisher requires exactly one generated section, ignores headings and
  markers inside code fences, refuses human-authored lookalikes and changes
  `updated` only on a real write.
- Poor-grade backlog escalation remains independent and deduplicated.

PRJ-LazyHarness still needs reviewed archival and explicit marker insertion.
The harness does not mutate the vault or opt a project in implicitly.

## 0.74.1 audit findings

| Finding | Resolution |
| --- | --- |
| Unbounded `queue/done/` | Worker prunes task files older than seven days; `lh status queue` already reported the done count, so no duplicate diagnostic was added. |
| Missing profile skills | ADR-059 projection implemented, including legacy Claude migration. Installed deployment waits for merge/release by the binary-first rule. |
| Full proposal queue | Eleven verdicts are prepared, but applying them changes the external knowledge store and still requires explicit user authorization. No proposal was silently discarded. |
| Codex trust keyed by position | Re-audit found current trust state is keyed by the actual upstream key and checked against deterministic generated content, including stale and orphan detection. No replacement implementation was justified. |
| Repository hygiene | Stale clean worktrees found by the earlier audit were reduced. Dirty or unmerged user work remains untouched and is reported, not deleted. |
| Profile asymmetries | Report-only as requested; no policy was inferred from different commands, skills, models or ambient credentials. |

The audit-report workflow now matches its rule: `reports/**` is explicitly in
`specs/workflow/doc-short-path.md`.
